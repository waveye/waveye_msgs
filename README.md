# waveye_msgs

ROS 2 (Foxy) messages for Waveye radar object tracking.

- `waveye_msgs/msg/TrackedObject`
- `waveye_msgs/msg/TrackedObjectList`

## Build and install

The repo root is a colcon workspace (the package lives in `src/waveye_msgs`). You can build here, or clone the repo into your own workspace's `src/` and build there.

1. Source ROS 2:
```
source /opt/ros/foxy/setup.bash
```

2. From the workspace root, clean any previous build (optional but recommended):
```
rm -rf build/waveye_msgs install/waveye_msgs
```

3. Build:
```
colcon build --packages-select waveye_msgs --symlink-install
```

4. Source the workspace:
```
source install/setup.bash
```

5. Verify:
```
ros2 interface list | grep waveye_msgs
ros2 interface show waveye_msgs/msg/TrackedObject
ros2 interface show waveye_msgs/msg/TrackedObjectList
```

For quicker iteration, an alias (adjust the workspace path):
```
alias build_msgs='cd ~/ros2_ws && rm -rf build/waveye_msgs install/waveye_msgs && source /opt/ros/foxy/setup.bash && colcon build --packages-select waveye_msgs --symlink-install && source install/setup.bash && cd -'
```

## Changing messages

### 1. Edit the schema

- Modify fields in `src/waveye_msgs/msg/*.msg`.
- For a new message, add the `.msg` file and list it in `rosidl_generate_interfaces` in `src/waveye_msgs/CMakeLists.txt`.
- If a message uses types from another package, add that package to:
  - `find_package(...)` and the `DEPENDENCIES` list in `CMakeLists.txt`
  - a `<depend>` entry in `package.xml`

### 2. Rebuild and regenerate code

C++ headers and Python modules are generated by `rosidl` at build time. They are not checked in, so never edit them by hand. Rebuild with the steps in [Build and install](#build-and-install), then check the output:

```
ros2 interface show waveye_msgs/msg/TrackedObject
ls install/waveye_msgs/include/waveye_msgs/msg/
```

C++ users include the generated headers like this:
```cpp
#include "waveye_msgs/msg/tracked_object.hpp"
#include "waveye_msgs/msg/tracked_object_list.hpp"
```

After a schema change, rebuild every package that depends on `waveye_msgs` (for example `colcon build --packages-above waveye_msgs`). Stale builds fail to compile, or silently can't talk to nodes built against the new definition.

### 3. Compatibility

Any change to a message's fields (adding, removing, renaming, reordering, or changing a type) changes the message type. Nodes built against the old and new definitions won't communicate, and bags recorded with the old definition won't play back as the new type. Roll changes out to all publishers and subscribers together.

### 4. Bump the version

Update `<version>` in `src/waveye_msgs/package.xml`:
- patch: comments or docs only
- minor: new messages, nothing existing changed
- major: any change to an existing message

### 5. Build the Debian package

Requires `bloom` and `fakeroot` (`sudo apt install python3-bloom fakeroot dpkg-dev debhelper`).

```
source /opt/ros/foxy/setup.bash
cd src/waveye_msgs
rm -rf debian .obj-*
bloom-generate rosdebian --os-name ubuntu --os-version focal --ros-distro foxy
fakeroot debian/rules binary
```

This writes `ros-foxy-waveye-msgs_<version>-0focal_amd64.deb` to `src/`. To install it:
```
sudo apt install ./src/ros-foxy-waveye-msgs_<version>-0focal_amd64.deb
```

`debian/`, `.obj-*/` and `*.deb` are build output. They are gitignored and regenerated each time.
